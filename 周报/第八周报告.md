## 四、TC-10 输出乱序问题修复

### 问题现象

合并后运行 `timertest`，TC-10 的输出出现字符交错，如：

```
n=0timers: insert took 0 tick(s)bgbgn= 50timers:inserttook0tick(s)...
```

### 根本原因

console task 运行在 level 2，priority=2（每 20ms 触发一次 task switch）。`cons_putstr0` 逐字符输出，每输出若干字符就可能被 timer 中断打断并切换到其他 console task，导致多个 task 的输出交错写入同一屏幕区域。

此外，TC-10 原始实现中背景定时器的超时值设为 500~1500 tick，这些定时器在测试运行期间会真正触发，向 `task->fifo` 写入数据，进一步加剧了输出时序的混乱。

### 修复过程

**第一步**：将背景定时器超时值从 500~1500 tick 改为 50000+ tick，避免测试期间触发。问题未完全解决，说明根本原因是 task switch 打断输出，而非定时器触发。

**第二步**：将 4 次迭代的测量结果先全部收集到数组，再统一输出。问题仍存在，因为 `cons_putstr0` 本身仍是逐字符的，输出期间照样会被打断。

**第三步**：将所有输出内容拼接到单个缓冲区，用 `io_cli` 关中断后一次性调用 `cons_putstr0`，输出完成后 `io_sti` 恢复中断。关中断期间 timer 中断无法触发，task switch 不会发生，输出原子完成。同时将每行格式缩短（去掉冗余的 "bg timers: insert took" 前缀），降低缓冲区压力。

**最终修复代码**（`kernel/console.c`）：

```c
{
    char out[256];
    int pos = 0;
    for (k = 0; k < 4; k++) {
        sprintf(s, "n=%3d: %u tick(s)\n", n_bg[k], tc10_ticks[k]);
        for (i = 0; s[i] != 0; i++) out[pos++] = s[i];
    }
    sprintf(s, "(0 tick = sub-10ms, expected)\n");
    for (i = 0; s[i] != 0; i++) out[pos++] = s[i];
    out[pos] = 0;
    io_cli();
    cons_putstr0(cons, out);
    io_sti();
}
```

修复后输出干净：

```

n=  0: 0 tick(s)
n= 50: 0 tick(s)
n=100: 0 tick(s)
n=200: 0 tick(s)
(0 tick = sub-10ms, expected)
```
