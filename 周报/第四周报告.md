## 二、原理与结构归纳

### 2.1 硬件层：8254 PIT + 8259 PIC

系统以 **8254 PIT 通道0** 为唯一硬件节拍源，配置如下（`timer.c:37-39`）：

```c
io_out8(PIT_CTRL, 0x34);  // 通道0，方波，16位计数
io_out8(PIT_CNT0, 0x9c);  // 计数值低8位
io_out8(PIT_CNT0, 0x2e);  // 计数值高8位
// 计数值 = 0x2e9c = 11932，PIT时钟1.19318MHz
// 中断频率 ≈ 1193180 / 11932 ≈ 100 Hz，即每10ms一个tick
```

PIT 产生的中断经 **8259A 主PIC 的 IRQ0** 送入CPU，对应 IDT 向量号 `0x20`（`dsctbl.c:48`）：

```c
set_gatedesc(idt + 0x20, (int) asm_inthandler20, 2 * 8, AR_INTGATE32);
```

`bootpack.c:105` 中将 PIC0_IMR 设为 `0xf8`，即开放 IRQ0（定时器）、IRQ1（键盘）、IRQ2（级联），其余全部屏蔽。

### 2.2 软件层：定时器管理结构

软件定时器由 `bootpack.h` 中两个结构体管理：

**`TIMER` 结构体**（单个定时器）：
```c
struct TIMER {
    struct TIMER *next;      // 链表指针，指向下一个到期更晚的定时器
    unsigned int timeout;    // 绝对到期时刻（tick数）
    char flags;              // 0=未用, 1=已分配, 2=运行中
    char flags2;             // 用于 timer_cancelall 标记
    struct FIFO32 *fifo;     // 到期时向哪个FIFO投递数据
    int data;                // 投递的数据值
};
```

**`TIMERCTL` 结构体**（全局控制器）：
```c
struct TIMERCTL {
    unsigned int count;              // 全局tick计数，每次IRQ0+1
    unsigned int next;               // 链表头定时器的到期时刻（快速判断用）
    struct TIMER *t0;                // 按到期时间升序排列的链表头
    struct TIMER timers0[MAX_TIMER]; // 定时器对象池，MAX_TIMER=500
};
```

**核心设计**：定时器池 `timers0[500]` 静态分配，`t0` 指向一个**按 `timeout` 升序排列的单向链表**，链表尾部有一个哨兵节点（`timeout=0xffffffff`），避免遍历时越界。

### 2.3 关键接口分析

**`timer_settime()`**（`timer.c:79`）——插入链表：
```c
timer->timeout = timeout + timerctl.count;  // 相对超时转绝对时刻
// 从链表头遍历，找到第一个 timeout 更大的节点，插入其前
```
时间复杂度 O(n)，n 为当前活跃定时器数量。并发安全依赖 `io_cli()`/`io_store_eflags()` 保护。

**`inthandler20()`**（`timer.c:110`）——中断服务程序：
```c
timerctl.count++;
if (timerctl.next > timerctl.count) return;  // 早期返回优化
// 遍历链表，处理所有 timeout <= count 的定时器
// 普通定时器：fifo32_put() 投递数据
// task_timer：设 ts=1，最后调用 task_switch() 触发任务切换
```
`timerctl.next` 缓存了链表头的到期时刻，使得绝大多数 tick 只需一次比较即可返回，极大降低中断开销。

**`timer_cancel()`**（`timer.c:142`）——从链表摘除：
分两种情况处理：摘除链表头节点，或摘除中间节点，全程 `io_cli()` 保护。

### 2.4 与任务切换的交互

`mtask.c` 中 `task_init()` 分配了专用的 `task_timer`，通过 `timer_settime(task_timer, task->priority)` 设置时间片长度。`inthandler20` 检测到 `task_timer` 到期时调用 `task_switch()` 完成时间片轮转。这意味着**任务调度完全依赖定时器链表的正确性**，定时器管理出错会直接导致调度失效。

## 三、后续实验方案初定

基于以上分析，确定后续实验围绕三个方向展开：

**方向一：并发压力测试**
在现有 API 下同时激活大量软件定时器（目标 ≥60 个），验证链表插入、到期触发、链表摘除的正确性。重点观察：
- 到期顺序是否严格按 timeout 升序
- 是否存在漏触发或重复触发

**方向二：边界条件测试**
- 池耗尽：连续分配直到 `timer_alloc()` 返回 0
- `timer_cancel` 边界：取消已到期的、未到期的、已取消的定时器
- 超时值边界：timeout=0（立即到期）、timeout 极大值

**方向三：并发安全验证**
- 定时器压力测试期间同时触发键盘中断（IRQ1），确认 IRQ0 与 IRQ1 无竞态
- 验证 `timer_settime` 中 `io_cli` 保护区间的有效性

测试环境：QEMU 模拟器 + 内核控制台输出，记录方式为控制台日志计数与截图存档。
